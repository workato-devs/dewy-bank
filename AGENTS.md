# AGENTS.md: rules for agents working in this project

`dewy-bank/` is **one** `wk` project for the whole workshop. Read `README.md` first, then the station's own rules:

- Station A: [`docs/station-a/AGENTS.md`](docs/station-a/AGENTS.md)
- Station B: [`docs/station-b/AGENTS.md`](docs/station-b/AGENTS.md) (`dewy-bank-station-b/` is generated by `scripts/build/build_station_b.py`; don't hand-edit it)
- Station C: [`docs/station-c/AGENTS.md`](docs/station-c/AGENTS.md) (`dewy-bank-station-c/` is generated by `scripts/build/build_station_c.py`; don't hand-edit it)

## Project layout rules

1. **One `.wk/` and one `.wk/wk.toml`, at this root.** Never create a `wk` project inside a station or a subfolder.
2. **Every synced folder is a root-level sibling named after its server folder** (kebab-case: `Dewy Bank Station A` becomes `dewy-bank-station-a/`). Never nest a synced folder (no `references/…`, no `<station>/station_a/`). Cross-folder `zip_name` paths such as `Workspace Connections/dewy_bank_customer_api.connection.json` assume this.
3. **Synced folders hold only Workato assets.** READMEs, AGENTS files and requirements go in `docs/<station>/`; scripts go in `scripts/`: workshop tools (`stamp_bank_app_url.py` for facilitators, `setup_chat_clients.py` for participants) at the top, content-build tools (the station builders and invariant checks) in `scripts/build/`; the bank's code (CDK stack, Lambdas, web app) goes in `infra/`, which is never a `[[sync]]` entry. Superseded docs that code still cites go in `docs/history/`.
4. **Shared connections only.** Every Station A and B recipe calls the `Dewy Bank Customer API` custom connector through `Workspace Connections/dewy_bank_customer_api.connection.json`, as the participant. The connector's code is `workspace-connections/dewy_bank_customer_api.custom_adapter.rb`; when you change it, change the `.custom_adapter.json` too, or the push fails ("Package doesn't contain any assets"). Connection names are unique per workspace, so never add a per-station `connections/` folder. `wk pull` doesn't bring the connector back, so the repo is its source of truth. The connector asks participants for nothing but their own Dewy Bank email and password: it discovers the deployment from the bank app's `config.json`, and the bank app's URL is stamped into its code per workshop (`scripts/stamp_bank_app_url.py`). The Support API connector asks for one thing: the support code. Never add a connection field for something the workshop already knows. **A connection's provider can't change in place:** switching one from the built-in HTTP connector to a custom connector means deleting the server connection first (`wk connections delete <id>`), then pushing, then force-pushing the recipes that use it.
5. **`Workspace Connections` is the first `[[sync]]` entry, always.** wk pushes one entry at a time, in `wk.toml` order. In a blank workspace (the participants' case), the stations' recipes bind to the shared connection only if it was imported first. wk may drop the comment in `wk.toml` when it rewrites the file; this rule is the record.
6. **`workspace-connections/` ships only the Dewy files** (the Customer API and Support API connectors and their connections, `project.json`). Don't `wk pull` that folder in a workspace where other apps use it. **Deleting a file locally doesn't delete it on the server:** `wk push` reports `deleted`, but the asset stays (observed twice, 2026-10-20). Delete obsolete recipes with `wk recipes delete <id>`; skills and connectors can only be deleted in the Workato UI.
7. **The committed `.wk/wk.toml` is workspace-neutral:** `name`, `description` and the `[[sync]]` `server_path`/`local_path` pairs only. `wk link` and `wk push` write `profile`, `email`, `workspace_id`, `folder_id` and `project_id` into it. Strip those before committing; they point at your workspace, not a participant's. `.wk/.gitignore` keeps everything else in `.wk/` out of git.
8. **To move a synced folder:** change its `local_path` in `.wk/wk.toml`, move its state directory from `.wk/<old local_path>` to `.wk/<new local_path>`, and confirm that `wk push --dry-run` shows every file `unchanged`.

## Before you change a station (content authors)

This is build time, for whoever authors the workshop content. Participants only ever `wk push` what's committed, and their workspace is theirs to change.

```bash
python3 scripts/build/build_station_b.py && python3 scripts/build/check_invariants.py
python3 scripts/build/build_station_c.py && python3 scripts/build/check_station_c.py
python3 scripts/build/check_recipe_structure.py   # what activation rejects and lint misses
wk lint --skills-path <path-to>/recipe-skills/skills $(find dewy-bank-station-* -name '*.recipe.json')
wk push --dry-run -p <profile>     # read it for `deleted` rows
wk push -p <profile>               # never `wk recipes import` (it strips HTTP config)
```

Commit the rebuilt `dewy-bank-station-b/` and `dewy-bank-station-c/` with the change. CI (`.github/workflows/stations.yml`) rebuilds them on every pull request, fails if the committed files are stale, and runs both invariant checks and the structure check; `wk lint` stays local, because it needs the wk CLI and the recipe-skills checkout.

Pass `-p <profile>` on every `wk` command, and pick the profile by the account email behind it (`wk workspace info -p <profile>`), not by its name.
